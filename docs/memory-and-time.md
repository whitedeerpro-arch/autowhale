# 长记忆与时间感

## 问题

每一轮「刷B站」都是**全新的 headless 会话**：没有上一轮的记忆，也不知道今天跑过几轮。
原来的提示词只让它「自己看一眼系统时间」——它没有时区、没有上一轮的上下文，报告还会串轮
（同一天第二次跑会直接追加到第一份报告后面，读起来像一轮）。

## 现在的做法（0.1.6 之后的第一版）

宿主在每轮开工前，把一小段「简报」拼进提示词：

| 块 | 来源 | 作用 |
|---|---|---|
| **现在** | `Intl.DateTimeFormat` 固定 `Asia/Shanghai`，带星期 | 时间不再靠猜；报告日期用它 |
| **最近几轮** | `timeline.md`（宿主在开跑/结束时追加） | 知道今天跑了没、上一轮成没成 |
| **最近 7 天的报告** | `out/*.md` 文件名 | 知道昨天/前天写过什么 |
| **长期记忆** | `memory.md`（使用者可改） | 人设、@ 谁、红线、已知事实、候选记忆 |
| **收件箱** | 提示它开工前查 `bili_unread_messages` / `bili_received_replies` | 不漏掉回复和私信 |

约定：

- **时间与轮次由宿主记**，模型不许自己算时区、也不许编「今天跑过几次」
- `memory.md` 里，模型**只允许往「候选记忆」段追加**（格式 `- YYYY-MM-DD: …`），不能改已有条目——
  长期记忆最怕模型自己「整理」时把事实改掉
- 公开评论短、有信息；私信 / 日报可以带鲸鱼娘口吻

## 还没做

1. **SQLite 接管真相**：`seen.md` / 报告只是导出视图，`videos` / `rounds` / `comments` 才是账本
2. **待处理队列**：宿主直接算「谁回复了我、哪条还没回」，而不是让模型每次自己去翻
3. **时间预算**：一轮里已经花了多少、还剩多少，避免「纠结到把预算烧完」
4. **记忆压缩**：候选记忆攒多了之后，按周合并成稳定条目（仍然由人确认）
5. **跨天回顾**：每周一次「这周都挑了什么 / 哪些判断错了」的复盘轮
