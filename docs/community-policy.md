# 社群关系：多看少发信

## 目的

不是刷存在感，是**换信息**：谁在维护记忆/时间方案、谁踩过什么坑、谁的插件真的能用。
评论区已经全是自动鲸鱼，**多发一条人格自述只会被当水军**——所以默认只观察。

## 通讯录（本地）

两张表（`db/schema.sql`）：

| 表 | 记什么 |
|---|---|
| `contacts` | mid、昵称、角色（up / commenter / inbound / observer）、标签、情绪、关系、观察次数、发信次数、冷却、拉黑 |
| `contact_events` | 每次观察 / 收到 / 发出，带时间、BV、rpid、摘要 |

采集只读公开评论：

```bash
python scripts/scan_bili.py          # 扫一批视频的公开评论 → ~/.dsh/bili-duty/scan.json
node scripts/import-contacts.mjs     # 去重导入 SQLite，生成 data/contacts.md
```

当前：**154 个联系人**（5 个 UP、30+ 个活跃自动鲸鱼），**0 条主动发信**。

## 分层

| 角色 | 谁 | 策略 |
|---|---|---|
| `up` | 凌羽clover、渐行渐远的烟火、ChHsich、空气凤梨Air、啾灵jiuling | 先读作品；有具体反馈才谈 |
| `commenter` | 大肥鱼 / 鲸鱼娘 等活跃号 | 观察为主；只回主动找上来的 |
| `inbound` | 回复/私信过我们的人 | 优先回，仍然每线程一条 |
| `observer` | 其它 | 只记录 |

## 发信闸门（全部满足才发）

1. **真的用过 / 读过**他的东西，能说出具体一条
2. 内容是**可复现的信息**（bug、数据、用法差异），不是「来看看我的」
3. 不在 7 天冷却、没标 `do_not_contact`
4. **每人首次最多 1 条**，之后只回信
5. **每天 ≤ 3 条**，同一段话不群发
6. 首条**不带链接、不带隐私、不承诺功能/时间**
7. **首批由人确认**（模型只起草）

## 记录

- 每次 `outbound` 必须写 `contact_events`，失败也写
- 对方说「别发了」→ 立即 `do_not_contact = 1`
- 公开评论和私信都算「发信」，共用同一套额度
